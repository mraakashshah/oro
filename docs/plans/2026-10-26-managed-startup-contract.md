# Managed startup authority and first source consumer

Status: Astra design proposal, not implemented or runtime-qualified. Reconcile the existing task contracts and split each large contract into bounded sequential leaves before implementation. The first source milestone is not delivery or autonomous recovery.

Decision: use three sequential, compiling contracts below as ONE integration milestone. The first two are prerequisites, not production-wiring acceptance on their own. Do not add a CLI call to a nonexistent RunManagedController. Do not expose a source-preparation API. No current code implements Supervise, RunManagedController, controller launch, or activation; docs/plans/2026-10-23-unattended-factory-tasks.md explicitly leaves activation decomposition open. Generic reserveBudget/controller and reserveScope are not an authenticated startup producer.

Existing reuse: managed_store.go beginGeneration/advanceEpoch, reserveManagedToken, insertScope, RecordHello/Granted/Observe; managed_admission.go committed manifest and snapshot; managed_admission_view.go immutable view; cmd_factory_budget.go persistent allocation; cmd_factory_runtime_config*.go verified runtime format/reader; cmd_factory_docker_storage_config.go newFactoryDockerConfigReader; launchd host socket peer-authentication, strict frames, exact-label retirement; raw source_git export; managedDockerVolumes.prepareSource. Preserve the controller/backend seam and legacy Run.

## Contract 1 — persist activation and counted controller intent

New pkg/factory/managed_startup.go; minimal DDL in managed_store.go; startup checks in RecordHello/Granted in managed_store.go. Tests: new managed_startup_test.go. The eventual actual consumers are Supervise and RunManagedController in contract 2; CLI publication in contract 3. Do not close this as integrated before contract 3.

Add concrete exported ManagedRuntimeReference {Path, SHA256 string}, ActivateManaged(ctx,stateDir,id string, ref ManagedRuntimeReference) error, and ReadManagedRuntimeReference(ctx,stateDir,id string) (ManagedRuntimeReference,error). This is a fixed artifact reference, not an options/provider framework. Activation trusts the CLI publisher as existing admission trusts its caller; CLI verifies bytes and artifacts before calling. Core checks canonical exact objective/runtime/runtime.json layout, lowercase digest, committed admission identity, and original time bounds. The reference is immutable, persisted in the journal and supplies startup digest authority; a hash freshly calculated from runtime.json is never authority.

Fresh admission creates managed_activation with a single pending row bound to admission identity. ActivateManaged atomically changes pending -> active plus exact runtime reference only after checking no execution reservations/scopes and no stopping/terminal state. Identical active replay is read-only; conflicting reference, aborted/missing/corrupt row, old objective without this schema, or any ambiguous prior execution rejects. Never auto-activate old admissions or rebuild missing activation history. No abort/release shortcut in this slice: interrupted initialization retains its existing reservation until a separately implemented proven abort. Account fixed bounded activation bytes inside the existing journal allowance.

Private reserveManagedController(ctx,j,supervisorToken string,generation uint64) (ScopeHandle,error) generates random ID/nonce, exact controller launchd name and original work deadline. In ONE j.mutate transaction: require exact active activation; current supervisor token/generation/running state; original work deadline; restart backoff elapsed; every old scope positively quiescent; no active cleanup; reserve controller token=scope.ID under MaxControllerStarts; insert controller scope; write event. No separate reserveBudget+reserveScope window, no refund. No new generic public reservation API.

Private requireManagedController(ctx,tx,j,state,scope) verifies complete canonical scope, controller token=scope.ID and same generation, exact name/backend/deadline, activation and runtime reference, active ownership, and lifecycle. Apply to controller RecordHello and Granted in their existing transactions. Generic reserveScope must reject controller kind, as it already rejects cleanup; only the atomic producer may create it. RecordHello uses backend-authenticated real PID/UID and requires PID=PGID>1 for this direct launchd job. A random scope or ordinary H reservation cannot become controller authority.

Acceptance: atomic failure rollback; exhausted budgets; duplicate producer race; inactive/changed activation; revoked/late/wrong-generation HELLO/GO; missing controller reservation; unchanged deadlines and counters on replay. Zero backend effects on failure. Existing generic tests that synthesize controller scopes must be replaced with typed startup fixtures rather than a production bypass.

## Contract 2 — actual core producer and worker-checkout consumer

New pkg/factory/supervisor.go, managed_engine.go, managed_backend.go, managed_workspace.go; minimal workspace DDL in managed_store.go. These are sequential leaves inside this contract, not a claimed seven-minute task. Tests: supervisor_test.go and managed_engine_test.go. Do not include candidate/model/acceptance implementation here.

Implement the designed Supervise(ctx,stateDir,id string,backend SupervisorBackend) (Status,error). Hold lockManagedSupervisor; verify activation/admission; spend incarnation with beginGeneration before backend action; enumerate canonical old scopes, retire and positively observe them, then call reserveManagedController and backend.StartController. A bootstrap error remains an uncertain counted scope, never a second dispatch. Poll durable snapshot/scope state within original bounds, maintain the frozen restart backoff, and require retirement before another counted start. Existing Docker uncertainty remains stopping/charged; do not claim unknown-daemon recovery. No fake success or absence-as-retirement. Add a backend-independent startup producer test that observes the actual StartController call receiving its committed scope.

Implement RunManagedController(ctx,stateDir,id string,generation uint64,token string,host HostRuntime,readDockerConfig ManagedDockerConfigReader) (Status,error). token is controller scope.ID, not SupervisorToken. Open existing FULL journal/store without schema initialization; take objective lock; verify immutable admission and active runtime reference; load full controller scope by token; require authenticated granted state and local os.Getpid()/process group equal its recorded PID/PGID; enforce exact generation/deadline. Never admit, activate, start an epoch, or reserve its own controller start. Construct newManagedGitRepository and newManagedDockerVolumes using these same manifest/journal/host dependencies; reader result path/digest must equal active reference, beyond existing manifest checks.

Managed worker checkout is a real managedDeliveryBackend.checkout implementation consumed by controller.attempt. It persists a bounded workspace record BEFORE calling raw export or prepareSource. Key: admission hash, controller scope ID, generation, attempt, literal worker stage, base SHA; random opaque workspace ID is the controller's Worktree token, never a host path. Record contains original checkout deadline, phase preparing/ready/interrupted, and zero-or-exact keeper handle. Its unique key prevents a second preparation dispatch. Limit rows by existing source-version allowance; each record <=2KiB and charge it within the associated existing scope metadata allowance (verify the retention arithmetic before adoption; no implicit increase).

checkout calls managedGitRepository.export(base), then prepareSource with the SAME outer context bounded by frozen checkout deadline. Store ready+keeper only after real preparation succeeds, rechecking active controller authority and exact association. Reopen preparing without keeper never calls prepareSource again: retain owned resources and route to supervisor retirement; ready reuse calls resumeSource, requiring original seed and keeper continuity. A death between allocation and association does not authorize adoption/replay; all leaf resources already exist in journal. Other stages must not borrow the worker workspace.

At this milestone candidate execution is still unavailable. Return a precise nonterminal interrupted/unavailable error preserving the spent attempt and prepared workspace; do not use legacy controller.reject to loop or erase ownership. Implement an internal managed-stage-unavailable error recognized by controller.attempt as a propagated interruption, preserving legacy behavior for all existing backend errors. Supervise must persist stopping on this non-retryable capability limitation, retire exact resources, and report incomplete/failed service outcome, never completed delivery. This is an unfinished production path, not a successful factory run. Do not enable it for real objectives as a delivery feature until candidate execution exists.

Acceptance: actual controller.attempt -> managed checkout -> raw export -> eight-call prepare composition; no legacy exec; original attempt/deadline unchanged across injected death boundaries; one workspace per attempt/stage; no replay from ambiguous preparing; bad token/config stops before Git/Docker; typed unavailable outcome does not burn all attempts. Recording tests prove ordering/state only.

## Contract 3 — CLI publication, supervisor launch, authenticated controller launch

New cmd/oro/cmd_factory_start.go, cmd_factory_supervise.go, cmd_factory_controller.go, cmd_factory_controller_launch_darwin.go (plus unsupported-platform file), cmd_factory_service.go. Register only implemented commands in cmd_factory.go. Reuse current private-artifact publication/ownership verification and launchd XML primitives; do not loosen factoryJobPlist's host-wrapper contract to accept arbitrary controller argv.

factory start: strict ManagedSpec -> admitFactoryHostBudget with real disk probe -> AdmitManaged -> ReadManagedAdmission -> freeze exact Oro binary and runtime/context artifacts using the existing canonical runtime format -> verify via existing runtime reader -> ActivateManaged(reference) -> register the exact owned stable supervisor job. Persist service identity/registration intent before bootstrap; uncertain registration is reconciled by that identity, never random replacement. Start never releases its live reservation. Resume uses core ReadManagedRuntimeReference, not user-supplied digest or current installed executable. Idempotent same start preserves budgets and activation.

_supervise reads the active reference/admission, constructs the concrete factorySupervisorBackend with frozen config, then calls Supervise. The backend embeds/reuses the existing host runtime for H/observer/cleanup; implements exact controller StartController/Retire/Quiescent plus releaseFactoryHostReservation. A new direct controller one-shot renderer launches frozen Oro factory _controller with exact scope, active reference and owned handshake socket. Before bootstrap persist a bounded immutable startup envelope binding these fields; server validates real Unix peer UID/PID and PGID, exact scope/envelope digest, calls existing RecordHello, then sends one-shot GO. Reuse frame/socket authentication primitives; do not implement a second result-publication protocol. StartController returns after timely GO; exit/outcome is observed from durable state plus exact job retirement. Replayed HELLO never grants a different process.

_controller performs handshake before any work/descendants, rechecks deadline and authenticated grant, then reads admission+active reference, verifies runtime bytes, builds factoryLaunchdConfig, opens openFactoryLaunchdRuntime, and calls the IMPLEMENTED RunManagedController(..., runtime, newFactoryDockerConfigReader(view,ref.Path,ref.SHA256)). Core checks process identity again. Direct invocation without granted matching PID/PGID fails. Preserve hard-stop outside journal and unsuccessful-supervisor restart policy; uncounted startup failure exits zero with bounded diagnostics to avoid a launchd loop.

First real integration test: cmd/oro TestFactoryManagedControllerSource (recording process/service transport first, opt-in native separately) enters the actual start/_supervise/_controller commands, uses production activation and reservation producers, verifies exact startup-bound digest handoff, and reaches raw export/production prepareSource. A fixture that manually inserts controller reservations/grants is NOT this integration test. Native proof additionally uses actual launchd, real HostRuntime, guard image and Docker; checks UID1000 overwrite/execute/nested-directory writes, source continuity, exact resource retirement and foreign sentinel. Enabled missing prerequisites fail, never skip. No native execution requested by this document.

Completion boundary: these contracts remove the missing producer and config-reader wiring and permit production-path source qualification. They do not implement candidate execution, stopped import, independent acceptance, real models or autonomous recovery. No task closure or full-goal completion follows from the source milestone alone.
